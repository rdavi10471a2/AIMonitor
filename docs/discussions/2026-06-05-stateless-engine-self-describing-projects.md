# Discussion notes — Stateless engine, self-describing watched projects, doc authoring

*Exploratory direction notes from a working session 2026-06-05. NOT a contract or decision yet —
candidate "next push." Captured per request after a long noodle that started from "add a logout
button to every page" and ended at "did I just reinvent CASE."*

## One-line thesis

A **deterministic, stateless monitor engine sitting over a probabilistic agent.** The engine
(Roslyn/MSBuild truth + the safe-edit gate + verifiable artifacts) constrains and grounds the
model. The model supplies synthesis and explanation; the engine supplies truth and safety.

## Core principles that fell out

- **The monitor rediscovers every time.** The index is a *fresh projection of the code*, never a
  stored parallel model. There is no second source of truth to drift. (This is the anti-CASE move.)
- **Docs are generated OUTPUT from code (code → docs), not code from a model.** The easy, safe
  direction. Output is verifiable (cites file:line, regenerate-and-diff) and disposable.
- **Comments are unsafe in machine-edited files** and that's still true mid-2026 — structurally, a
  comment is an assertion with no oracle (code has the compiler/index/tests; a comment has nothing),
  so it drifts silently. Better models lower the drift *rate*, not the *class*. It only flips if
  comments become machine-verifiable (derived from / checked against the AST). So: no free-prose
  comments in source; context lives elsewhere.
- **AI + index docs are >= human for everything derivable from code** — on completeness (every edge),
  consistency (one voice across N dirs), currency (regenerate vs. humans can't keep dozens of docs
  fresh), and verifiability (auditable against the index). The human's only edge is **non-derivable
  intent** (the "why": vendor-bug coupling, don't-refactor-legacy-Y), which is small and durable.

## Doc authoring = step 2 of AIFileContext

`AIFileContext` is currently maintained but **underutilized** — a per-file corpus of structured
intent (Responsibilities / Nuances / RelatedFiles) that nothing aggregates yet. Step 2 is the
**harvester**: run MCP over a directory -> compose the index-derived structure (the *what*) with the
AIFileContext + human-authored intent (the *why*) -> write that directory's `.md`, or author the
project's own `AGENTS.md` / `CLAUDE.md`. The intent is captured at the one moment it's known (the
edit) and kept fresh under the monitor's maintenance contract, so the "AI can't know intent" gap
dissolves — it's a maintained input, not a guess.

## The keystone: human region vs AI-maintained region

Generated docs use the `// <auto-generated>` / `.designer.cs` pattern, in prose:

- **AI-maintained region** — dataflow, structure, references. Clobbered and regenerated every time.
- **Human-editable region** — the non-derivable *why*. Regeneration MUST NEVER touch it.

This is what lets "regenerate every time" coexist with "don't lose the irreplaceable intent." The
feature-maps already encode it (Human Notes vs AI-Maintained Map). **Implementation care-point:** the
section boundary must be a machine-stable marker the generator treats as a hard wall, so a regen can
never bleed into the human zone even when the file's structure shifts.

## "It's all there" — plan + history live in the child

Put the **FeaturePlan and a curated change-history in the watched project itself.** Clone the repo /
open the sln in VS 2022 and you have the complete story: code (truth) + per-dir docs (what) + human
sections (why) + plan (how this change happened) + history (over time). A **self-narrating repo**.
This *dissolves* the earlier "how do we move docs to the child" question — nothing transports;
artifacts originate in the child via the same safe-edit loop (a `.md` is just watched source), and a
PR just references in-repo files.

**Invariant to hold (bumps "keep runtime state out of watched projects"):** separate **ephemeral
runtime** from **durable narrative**.
- Ephemeral (working candidates, staged temp, validation workspaces) -> stays monitor-side in
  `runtime/`. Never in the child.
- Durable narrative (plan, *curated* history, generated docs) -> goes in the child as committed files.
- Raw `workflow/history` ledger = monitor scratch; a curated projection of it = child artifact.

Role split: **monitor = stateless engine + its own self-docs; child = self-contained and
self-explaining; runtime/ = throwaway.**

## Did we reinvent CASE? Yes — minus what killed it

Same 40-year dream (coherent model, generate artifacts, capture rationale, keep in sync), on a
substrate that removes every CASE failure mode:

| CASE (died) | This |
| --- | --- |
| Stored model <-> code, brittle round-trip -> drift | No stored model; rediscover from code every time |
| Generate *code from model* (hard, rigid) | Generate *docs from code* (easy, disposable) |
| Protected regions in generated *code* (fragile, hated) | Human/AI region split in *docs* (low stakes) |
| Authored **UML** you must draw + sync (the burden) | Plain prose + throwaway boxes-and-arrows views; no authored model |
| Heavyweight, upfront, waterfall | Code-first, docs follow, regenerate continuously |

The ideas were right in 1990; the tooling to make them not-drift and not-a-burden (cheap fresh
derivation + AI synthesis + a verified edit gate + code-as-truth) only just showed up. CASE with the
code as the model, AI as the explainer, diagrams as throwaway views — without the UML.

## Adjacent pushes flagged (not this push, but on the map)

- **A curated corpus of examples** — "how to do X consistently" — patterns the agent reuses so
  vertical slices (like the ETL-field slice) are done the same way every time.
- **A style guide everyone agrees to** — so generated docs and human edits converge on one voice.
- **The Plan skill card + `FeaturePlan.md`** (the front rung): formalizes plan -> discover -> staged
  edits -> review -> record -> PR; the plan doubles as the resume/handoff artifact, which also caps
  session length (plan = session boundary). Trimming verbose tool output (overlay error walls, full
  source maps) is the other half of the long-session fix.
- **The PR rung**: purely allowlisted local `git`/`gh` (no MCP needed); prerequisite is wiring a
  remote + auth on the watched repo (currently none — deliberately deferred to avoid locking the
  sandbox to a work login). Account/host (personal vs work org) is the real decision there.
